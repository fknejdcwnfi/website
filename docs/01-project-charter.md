## 1. 一句話定位

> 一個只有角色的正方形動畫舞台，作為個人網站的視覺門面，並逐步演化成可精細控制的 2D 角色動畫系統。

它不是作品集、不是部落格、不是儀表板。
它首先是一件**視覺作品**，其次才是一個可維護的前端專案。

---

## 2. 背景

最初交付的素材是一組十張關鍵姿態：白金色長髮的角色，依序表現「靜止 → 起風 → 風力增強 → 半閉眼 → 閉眼 → 重新睜眼 → 陣風高峰 → 風向改變 → 風勢減弱 → 回到靜止」。素材同時附有：

- `10_frame_prompts.md`：逐幀動作描述與時間軸。
- `codex_prompt.md`：給前端／角色綁定工程師的完整任務書。
- 聯絡表與預覽 GIF：供人眼快速審閱。

這些圖**不是**逐像素一致的動畫幀，而是獨立的 AI 生成參考。因此本專案的核心工程問題不是「如何播放十張圖」，而是：

> 如何在保留原畫風與角色身份的前提下，用固定的臉 + 分層的髮絲／眼皮 + 可調的風力模型，做出真正無縫的動畫？

---

## 3. 產品原則

| 編號 | 原則 | 含義 |
| --- | --- | --- |
| P1 | **角色優先** | 畫面中只有角色；不加入導航、標題、按鈕、社群圖示。 |
| P2 | **身份鎖定** | 臉型、五官、眉眼、飾物附著點與鏡頭構圖不得漂移。 |
| P3 | **物理可信** | 髮根固定、髮尾延遲、慣性回彈；眨眼不靠縮放頭部假裝。 |
| P4 | **畫風不可協商** | 保留 crisp hand-drawn anime linework；禁止 pixel art、3D、重新設計。 |
| P5 | **可部署、可接手** | 任何人 clone 後可在數分鐘內跑起來；代理可依文件獨立工作。 |
| P6 | **尊重使用者** | 支援減少動態偏好、行動裝置、視網膜螢幕與低效能裝置。 |

## 4. 目標與驗收

### G1 · 可公開存取的舞臺

- 執行 `npm run deploy` 後，`dist/` 會發佈到 `gh-pages` 分支，GitHub Pages 從該分支提供網站。
- 選用：若 token 具備 `workflow` scope，可啟用 `deploy/github-actions/` 的自動部署。
- 訪客在 390 px 寬的手機與 1440 px 桌機都能看到完整正方形舞臺。
- **驗收**：`https://fknejdcwnfi.github.io/website/` 回傳 200，且無 console error。

### G2 · 時間軸正確

- 十個關鍵姿態依 `docs/03-animation-spec.md` 的時間表呈現。
- 循環長度 2300 ms；第 10 幀與第 1 幀完全相同，結尾無跳動。
- **驗收**：`?debug=1` 的 `t` 在 0–2299 ms 循環；`?pose=N` 可凍結任一幀。

### G3 · 視覺身份穩定

- 任一時刻的臉部幾何與第 1 幀一致；眼睛、鼻子、嘴巴不因逐幀生成而抖動。
- 飾物附著點不脫離耳朵與頸部。
- **驗收**：以第 1 幀為基準，將動畫截圖疊合；臉部特徵偏移需小於 2 px（以 1080² 計）。

### G4 · 頭髮是「局部變形」而非整圖平移

- 至少七組可獨立動畫的髮束：前額瀏海、左臉側、右臉側、左外層長髮、右外層長髮、肩部髮尾、後髮。
- 每組有固定髮根、相位差與阻尼；不得用整張圖的 CSS translate/rotate 模擬。
- **驗收**：凍結不同時間點，髮根位置不變，僅髮尾位移。

### G5 · 眨眼自然

- 開 → 半閉 → 全閉 → 開，全程 150–250 ms。
- 眼皮與睫毛位置穩定；虹膜在牛眼狀態仍可見；頭部不得縮放。
- **驗收**：錄影逐幀檢查；閉眼期間臉部輪廓不變。

### G6 · 效能與可及性

- 桌機與中階手機維持 55–60 fps；不得因解碼或配置造成長任務。
- 尊重 `prefers-reduced-motion: reduce`，顯示靜止第 1 幀。
- Canvas 具備可存取的 `role="img"` 與描述。
- **驗收**：DevTools Performance 錄製 5 秒，無 > 50 ms 長任務；強制 reduced motion 後畫面靜止。

### G7 · 可維護的交接

- 新人或代理只讀文件即可知道：現況、限制、下一步、禁止事項。
- 每次變更同步更新 `CHANGELOG.md` 與相關文件。
- **驗收**：文件內的指令可照抄執行；連結無 404。

## 5. 非目標（明確不做）

| 編號 | 非目標 | 理由 |
| --- | --- | --- |
| N1 | 多頁式個人網站、部落格、作品集列表 | 現階段只做單一視覺舞臺；內容架構另案討論。 |
| N2 | 使用者互動（點擊、拖曳、滑鼠追蹤） | 原始任務書要求「網站沒有其他功能」。 |
| N3 | 多角色切換 | 會迫使素材與 rig 抽象化，稀釋當前品質目標。 |
| N4 | 3D／WebGL 角色重建 | 與原畫風衝突，成本高且非必要。 |
| N5 | Pixel art、Minecraft 化、濾鏡風格化 | 明確禁止。 |
| N6 | 直接把十張圖輪播並稱為完成品 | 會產生閃爍與身份漂移，屬於欺騙性交付。 |
| N7 | 後端、資料庫、CMS、會員系統 | 純靜態網站即可滿足需求。 |
| N8 | 商業授權、角色再散布 | 角色權利不屬於本專案。 |

> **注意**：非目標不是「永遠不做」，而是「不在目前版本做」。若要變更，需提出 ADR 並更新本章程。

- [ ] 沒有把暫定方案描述成最終品質。

## 8. 風險與假設

| 風險 | 影響 | 緩解 |
| --- | --- | --- |
| 十幀之間臉部幾何不一致 | 交叉淡入殘影、身份漂移 | Stage 2 以第 1 幀為唯一乾淨底圖；局部補繪 |
| 遮擋區域（髮後、眼皮下）沒有原始像素 | 變形時露出破洞 | 先做 inpainting／clean plate，再建立圖層 |
| 行動裝置解碼 10 張大圖造成卡頓 | 首屏閃爍、掉幀 | WebP、預載、必要時降級為 720 px 變體 |
| Codex Cloud 無瀏覽器或美術工具 | 無法完成視覺驗收 | 提供可執行的自動化檢查與清楚的限制說明 |
| 角色權利限制 | 無法商業化 | 明確標示個人非商業用途 |

**核心假設**：擁有者希望這是一個長期可維護的作品，而不是一次性 demo。因此文件與可重現性優先於短期視覺捷徑。

## 9. 開放問題（需要擁有者決定）

1. 是否綁定自訂網域？若是，`VITE_BASE` 與 `og:image` 需調整。
2. 是否要在舞臺之外加入極簡的身份文字（例如名字或一句話）？目前嚴格遵守「只有角色」。
3. 目標裝置的最低效能基準是什麼（例如 2020 年中階 Android）？
4. Stage 2 是否允許使用外部 AI 分割／補繪工具？生成物要如何標註？
5. 是否需要英文版文件，或維持繁體中文即可？

在這些問題有答案前，代理應維持現狀，不要自行擴大範圍。
